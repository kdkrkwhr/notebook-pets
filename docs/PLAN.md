# 📒 공책 AI 키우기 — 기획서 v0.2

> 작성: 버섯쿵야(ops) / 2026-08-26 (v0.2: 크루 의견 반영)
> 상태: **기획 확정 대기** (대장님 결정사항 반영: 9종족/8속성/v1 전투 포함)
> 반영 의견: pm 종합안, infra(무시쿵야), dev(양파쿵야), qa(샤러리쿵야)

## 1. 컨셉

어릴 때 하던 공책 게임처럼, 내 AI 에이전트(Hermes + Discord)를 **디스코드에서 키우는 몬스터 게임**.

- 플랫폼: Discord (#공책 전용 채널 제안)
- 엔진: Hermes 에이전트
- SoT: JSON 파일 기반 상태 저장 (세션 컨텍스트 의존 금지)
- 이미지: image_generate (FLUX) — 디지몬풍

## 2. 아키텍처 원칙 (최우선)

| 역할 | 주체 | 담당 |
|---|---|---|
| 게임 로직 (스탯 계산·랜덤·쿨타임·전투판정) | **결정론 Python 스크립트** | 결과를 JSON으로 출력 |
| 해석·서사·감정표현 | 에이전트(LLM) | 스크립트 결과를 받아 캐릭터 말투로 중계 |
| 상태 저장 | 파일 SoT (`state/*.json`) | version 필드 포함 |

> LLM이 판정을 맡으면 들쑥날쑥해져서 게임이 무너진다. 판정은 스크립트, 이야기는 LLM. 이 경계를 절대 섞지 않는다.

## 3. 시작 플로우

```
!공책시작 → [스크립트] 랜덤 종족/속성 결정 → 공개
        → 이름 입력 대기 → 유저 입력
        → [스크립트] state/{user_id}.json 생성 (Lv1)
        → [이미지] 1단계 몬스터 생성 → 전송
        → 상태카드 출력
```

## 4. 종족 (9종) — 대장님 픽: B안 + 용족/식물족/유령족 추가

| 종족 | 이모지 | 성향 |
|---|---|---|
| 포유류족 | 🦁 | 균형형, 친밀도 상승 빠름 |
| 조류족 | 🦅 | 민첩 특화, 회피 성향 |
| 파충류족 | 🦎 | HP/방어 특화, 성장 둔함 |
| 기계족 | ⚙️ | 방어 최고, 친밀도 깊게 쌓아야 함 |
| 요정족 | 🧚 | 행운 특화, 포획/상태이상 보너스 |
| 괴수족 | 👾 | 공격 특화, 친밀도 낮으면 폭주(강하지만 제어 어려움) |
| 용족 | 🐉 | 올라운드 강함, 성장 느린 후반 캐리 |
| 식물족 | 🌱 | HP/재생, **광합성 — 포만감 감소 느림** |
| 유령족 | 👻 | 회피/변칙, 배틀 특수효과 |

## 5. 속성 (8속성) — 대장님 픽: 전부 통합

| 속성 | 이모지 |
|---|---|
| 불 | 🔥 |
| 물 | 💧 |
| 번개 | ⚡ |
| 자연 | 🌿 |
| 바람 | 🌪️ |
| 땅 | 🪨 |
| 빛 | ✨ |
| 어둠 | 🌑 |

### 상성표 (공격 기준 ×1.5, 나머지 ×1.0)

```
불    → 자연, 땅에 강함 / 물에 약함
자연  → 땅, 물에 강함 / 불에 약함
땅    → 번개, 불에 강함 / 자연에 약함
번개  → 물, 바람에 강함 / 땅에 약함
물    → 불에 강함 / 번개, 자연에 약함
바람  → 자연, 땅에 강함 / 번개에 약함
빛    ↔ 어둠: 서로에게 강함 (상호 ×1.5)
```

- 종족 × 속성 = **72조합**, 이미지 프롬프트는 "종족조각 + 속성조각" 합성으로 생성 (조합 수와 비용 무관)
- 랜덤: 완전 무작위, 길치 조합 제약 없음 (qa 요청사항 — 명시)

## 6. 진화 체계

| 단계 | 레벨 | 비고 |

| 구간 | 레벨당 필요 XP | 하루 평균 획득(모든 액션 소진 기준) | 소요일 |

| 1~30 | 100 | ~400 | 7~8일 |
| 31~50 | 200 | ~500 | 8일 |
| 51~80 | 400 | ~600 | 20일 |
| 81~100 | 800 | ~700 | 23일 |

- 총 기간 약 60일 — 너무 길면 조정 (튜닝 포인트는 구현 후 실측)
- 진화 3레벨 전부터 "몸이 빛나고 있다..." 예고 티저 출력

### 진화 분기

- v1: **친밀도 자동분기** — 진화 시점 친밀도 70↑ → 빛 계열 완전체 / 70↓ → 어둠 계열 완전체

```

[완전체] --Lv100--> [캡] --(P2)은퇴--> [없음, 도감 기록]
```

## 10. 이미지 파이프라인

1. 1단계 생성 시 프롬프트 템플릿 저장 (`prompts/{species}_{element}_lv1.txt`)
2. 진화 시: 이전 이미지 reference + 단계별 템플릿 → 연속성 유지
3. 실패 시: 재시도 2회 → 그래도 실패 시 이전 단계 이미지 유지 + 안내 메시지 (qa 요청 리트라이 정책)
4. 생성 수십 초 → "진화 중..." 선행 응답 후 전송

## 12. 구현 시 Git Repo (대장님 질문 답변)

**권장: 구현 확정 시 별도 repo 생성** (`D:\develop\project\notebook-monster` 등)

- workspace 규칙: 제품은 `project/`, 에이전트 산출물은 `reports/`. 게임은 프로젝트로 승격되므로 repo 필요
- dev complete 검증은 git diff 교차검증이 필수 — repo 없으면 diff 검증 자체가 불가능
- 버전관리 대상: 게임 로직 스크립트 / 프롬프트 템플릿 / state 스키마 / 기획서(docs/)
- **지금은 안 만든다**: 기획 확정 전엔 문서가 계속 바뀌어 repo 노이즈만 생김. 카드 분해 시점(승인 직후)에 repo init + 기획서 이동이 순서
