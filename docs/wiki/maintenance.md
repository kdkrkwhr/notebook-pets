# 위키를 읽고 갱신하는 방법

이 위키는 기능을 설명하는 한국어 문서와 Graphify가 추출한 자동 문서를 함께 제공해요. 두 종류는 갱신 방식과 근거가 달라요.

## 개발할 때 읽는 순서

1. [목차](index.md)에서 기능 해설을 읽고 책임을 맡은 파일을 찾아요.
2. 해설의 소스 링크를 열어 실제 구현을 확인해요.
3. [Graphify 목차](graphify/index.md)에서 주변 코드 묶음과 연결을 살펴봐요.
4. 코드를 수정하면 해당 동작을 검증하고 설명과 근거 목록을 함께 갱신해요.

LLM에도 같은 Markdown 파일을 참고 자료로 줄 수 있어요. 기능 해설은 `docs/wiki/`, 자동 문서는 빌드 후 `.local/architecture/graphify-out/wiki/`에 생겨요. 공개 사이트에서는 각 페이지의 **Markdown** 링크나 **문서 묶음**을 이용할 수 있어요.

## 자동으로 바뀌는 부분

Pages 빌드는 Git에 기록된 공개 앱 코드를 Graphify로 분석하고 `graphify export wiki`를 실행해요. 코드 묶음과 주요 연결의 문서는 새 분석으로 교체돼요. 이 과정은 로컬 정적 분석이며 LLM 호출이나 API 키가 필요하지 않아요.

자동 문서의 그룹 번호와 묶음은 소스 변화에 따라 달라질 수 있어요. 오래 유지할 개발 설명에는 기능 해설과 소스 링크를 사용하고, 자동 문서의 특정 그룹 번호를 영구 식별자로 삼지 않는 편이 좋아요.

## 설명은 소스를 읽고 갱신해요

한국어 해설은 LLM이 소스와 문서를 대조해 작성했어요. 배포할 때 문장을 자동으로 다시 쓰지는 않아요. `docs/wiki/catalog.json`에는 문서 순서와 설명, `docs/wiki/sources.json`에는 해설을 확인한 커밋과 참조 파일의 해시가 있어요.

빌드는 해설에서 링크한 근거 파일과 현재 Git 소스의 해시를 비교해요. 달라졌으면 해당 페이지에 **근거 변경 확인 필요**를 표시해요. 링크는 해설을 확인한 커밋으로 고정되므로, 최신 소스를 검증하지 않고 최신 설명인 것처럼 보이지 않아요. 이 표시는 참조한 파일의 변경만 감지하며, 문장의 정확성을 자동 검증하지는 않아요.

수정 후에는 해설을 다시 읽고 검증한 소스에 한해 커밋과 해시를 갱신해야 해요. 코드가 바뀌었다는 이유만으로 검토 표시를 지우면 안 돼요.

## 로컬에서 만들어 보기

```text
python -m pip install graphifyy==0.9.93 markdown-it-py==4.0.0
python tools/build_architecture.py
python web/build.py
node tests/pyodide/web-wiki.mjs
```

웹 빌드의 기존 Node·Pyodide 준비는 [웹 개발 안내](../../web/README.md)를 따라 해 주세요. 최종 결과는 `web/dist/wiki/`에 만들어져요. 게임 데이터나 유료 AI를 사용하는 테스트는 필요하지 않아요.

## 공개하는 범위

해설은 공개 저장소의 파일을 근거로 작성해요. 사용자 저장, 개인 대화, API 키나 로컬 설정은 수집하지 않아요. Graphify의 관계는 정적 분석 결과이므로 누락되거나 추론된 연결은 소스에서 다시 확인해야 해요. 위키만으로 현재 설치된 Anna 버전이나 심사 상태를 판단하지 않아요.
