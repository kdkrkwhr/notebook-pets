# 플랫폼과 데이터

Anna와 웹은 같은 게임 규칙을 사용하지만 로그인, 저장 위치와 AI 연결은 달라요. 웹의 공책이 Anna 계정으로 자동 동기화되는 구조는 아니에요.

## 플랫폼별 역할

| 항목 | Anna | 공개 웹 |
| --- | --- | --- |
| 실행 | Anna 도구 어댑터와 Python 코어 | 브라우저 Worker의 Pyodide와 Python 코어 |
| 게임 저장 | 인증된 APS 범위 | 현재 브라우저의 IndexedDB |
| AI 연결 | Anna Host API | 개인 키를 쓰는 Gemini 또는 설정한 Ollama·ComfyUI |
| 최초 그림·사진 분석 후 탄생 | 제공 | 현재는 완성된 그림 파일 가져오기 |
| 계정 간 동기화 | Anna 플랫폼 저장 범위 사용 | Anna와 자동 동기화하지 않음 |

근거는 [Anna Worker](../../anna/executas/notebuddy/game_worker.py), [Anna 어댑터](../../anna/executas/notebuddy/notebuddy_plugin.py), [웹 Worker](../../web/worker.js), [웹 AI 연결](../../web/ai.js), [웹 안내](../../web/README.md)에 있어요.

## 같은 내부 ID가 곧 사용자 공유를 뜻하지는 않아요

Anna Worker는 내부 플레이어 슬롯으로 `1`을 사용해요. 코드 주석과 어댑터 설계에서 실제 격리 경계는 Anna가 인증한 APS 버킷이에요. 숫자 `1`을 모든 사람이 쓴다는 이유로 하나의 저장 데이터를 공유한다고 해석하면 안 돼요.

다만 이 위키는 소스 구조를 설명해요. 운영 환경에서 여러 계정의 격리를 직접 검증했다는 뜻은 아니에요. 플랫폼의 실제 인증 동작과 앱에서 전달하는 대화 기록을 함께 확인해야 해요.

## 저장 충돌과 재시도

[store.js](../../web/store.js)는 웹 저장을 트랜잭션으로 처리하며 revision이 바뀌었으면 덮어쓰기를 거절해요. 초기화나 다른 친구로 교체하면 epoch를 바꾸고, 늦게 도착한 그림 응답이 다른 친구에게 붙지 않도록 검사해요.

Anna는 [receipts.py](../../anna/executas/notebuddy/receipts.py)와 [어댑터](../../anna/executas/notebuddy/notebuddy_plugin.py)에서 요청 결과와 저장 순서를 관리해요. 기존 저장의 ETag와 요청 ID를 이용해 충돌·중복 요청을 처리해요. 세부 정책은 [저장 정책](../../anna/docs/STORAGE_POLICY.md)에 있어요.

최초 데이터 생성의 동시성은 별도 한계가 문서에 남아 있어요. [FIRST_CREATION.md](../../anna/docs/FIRST_CREATION.md)는 두 독립 실행자가 비어 있는 저장소에 처음 쓰는 경우의 경쟁을 기록해요. 기존 상태 갱신의 충돌 검사만으로 최초 쓰기의 원자성이 보장된다고 설명하면 안 돼요.

## AI 연결과 비용의 경계

웹은 Anna 토큰을 사용하지 않아요. Gemini는 사용자가 설정한 키의 할당량과 요금, 로컬 AI는 사용자가 실행한 서버 자원을 사용해요. 웹 안내에 따라 API 키와 ComfyUI 워크플로는 현재 탭에서 사용하고 백업에 넣지 않아요. 모델과 연결 주소 같은 설정은 브라우저에 기억할 수 있어요.

Anna의 실제 모델 선택·할당량·요금은 플랫폼 정책과 실행 설정을 별도로 확인해야 해요. 앱 코드에서 `llm.complete()`를 호출했다는 사실만으로 특정 모델명이나 비용 부담을 단정할 수는 없어요.

## 위키 자체는 데이터를 읽지 않아요

이 위키의 검색은 배포된 문서 색인을 브라우저에서 찾아요. 게임 저장소, 개인 그림, 대화, API 키를 열지 않고 질문 응답용 AI도 호출하지 않아요. 공개할 내용은 Git에 기록한 코드와 위키 문서로 제한해요.
