# 대화 저장 재시도·미사용 초상화 정리

앱 **0.1.8**, 게임 도구 **0.1.6**. 기존 저장 형식과 권한은 바꾸지 않습니다.

## 대화 저장 재시도

AI 답변을 받은 직후 사용자/답변 한 쌍과 원래 메시지 ID를 창 메모리에 보관합니다. 저장 실패 시 새 대화 전송을 막고 저장 전용 재시도를 제공합니다. 다시 AI를 호출하지 않습니다. 저장은 최신 기록과 ID로 병합하므로 저장 성공 응답 유실·버튼 연타에도 같은 대화가 중복되지 않습니다. 저장 실패 직후 App Refresh나 언어를 바꿔도 미저장 답변을 표시합니다.

저장 성공 후 대화 전송을 다시 허용합니다. 저장 전에 게임과 삭제 표식을 확인하며 게임이 종료됐다면 미저장 대화도 지웁니다. 브라우저에 대화 원문을 영속 저장하지 않습니다. 창 종료/전체 페이지 새로고침 후 재시도는 이번 범위에 포함하지 않습니다. 기존 최대 24개 메시지 보관 정책을 유지합니다.

## 초상화 정리

앨범의 명시적 확인 동작으로만 실행합니다. 모든 기기의 다른 앱 창·그림 요청·업로드를 종료해야 하며, 현재 창의 그림 저장이 미완료라면 정리 버튼도 비활성화합니다.

1. 실제 게임 상태와 ETag가 있는 기존 앨범 인덱스를 읽습니다. 누락/삭제 표식/잘못된 경로는 삭제 없이 실패합니다.
2. `portraits/` 파일 목록을 최대 20×100개까지 모두 읽습니다. 페이지를 전부 수집하기 전에는 삭제하지 않아 삭제로 페이지 커서가 흔들리지 않습니다. 불완전한 목록·반복 커서·경로 이탈은 거부합니다.
3. 인덱스의 **모든 성장 단계**에서 참조하는 파일을 제외합니다. 현재 파트너/단계만 보존 대상으로 축소하지 않습니다.
4. 각 미사용 파일 삭제 직전에 게임/인덱스를 다시 읽습니다. 인덱스 ETag가 바뀌면 중단합니다. 파일은 목록의 ETag로 조건부 삭제합니다. 앨범 인덱스 자체는 수정하지 않습니다.
5. 부분 실패는 성공으로 표시하지 않고 재실행을 안내합니다. 이미 삭제된 파일이 있어도 다시 목록을 읽어 이어갈 수 있습니다.

참조 읽기와 파일 삭제는 원자적이지 않습니다. ETag는 파일 수정은 막아도 다른 키의 참조 추가를 잠그지 않습니다. 다른 창을 닫는 것은 실제 전제이며 전역 동시성 보장은 아닙니다. 원자적 최초 생성 출시 차단도 해결하지 않습니다. 인덱스 없이 남은 고아 파일, 2,000개를 넘는 목록, 영구 물리 삭제·서명 URL 만료는 별도 지원 범위입니다.

## 검증

- Node: 이전/현재 성장 그림 보존, 페이지 수집, 인덱스 누락/삭제/변경, 잘못된 경로와 커서, 파일 충돌, 중단·재개, 삭제 응답 유실.
- 실제 배포 UI + 모의 SDK 브라우저: 대화 실패 후 입력 복원, 저장 실패→Refresh/언어 전환→저장 응답 유실→중복 없는 재시도, AI 호출 수 불변, 삭제 후 재저장 차단.
- 브라우저: 초상화 정리 확인/취소, 부분 오류 후 재시도, 현재/이전 단계 보존, 진행 중 그림 저장에서 정리 차단.
- 실행: `npm test`, `npm run test:browser`, `npm run validate`. Windows/Linux CI에도 같은 검사가 들어갑니다. 모의 SDK 결과를 실제 APS 동시성 보장으로 해석하지 않습니다.

본인 파트너 모찌의 파일을 지우거나 테스트 대화를 보내는 방식으로 검증하지 않습니다. 실제 플랫폼 저장소 검증을 추가하면 격리 범위와 결과를 별도로 기록합니다.

## 실제 APS 저장소 검증 · 2026-10-09

기존 격리 앱 `notebuddy-erasure-check`에서 `maintenance-<UUID>` 전용 키 2개와 `portraits/maintenance-<UUID>/` 임시 파일 3개만 사용했습니다. 앱/도구 ID를 확인하고 기존 chat/art 삭제 표식이 그대로인지 전후 비교했습니다. 종료된 테스트 게임을 복원하거나 본 앱 저장소를 사용하지 않았습니다.

실제 앱 모듈의 저장소 어댑터만 테스트 키/파일 접두사로 좁혀 호출했습니다. 미사용 파일 1개 삭제, 이전/현재 단계 파일 2개 보존, 실제 저장 성공 뒤 응답 유실 주입 후 같은 대화 재저장 시 메시지 2개 유지를 확인했습니다. 사용한 임시 파일은 모두 제거했고 임시 KV 2개는 최소 표식으로 대체했습니다. SDK 연결과 실제 APS ETag/list/delete/set을 사용했지만 `assertActive`는 이 어댑터 검사에서 대체했으므로 전체 게임 UI 흐름의 실서비스 검증으로 표현하지 않습니다. UI 확인은 별도 브라우저 테스트가 담당합니다.

localhost 서명 PUT의 CORS 제약 때문에 SVG fixture 업로드만 Node에서 수행하고 SDK로 finalize했습니다. 서명 URL·인증 정보는 출력하지 않았습니다. 유료 AI 호출은 없었습니다. Windows Edge 브라우저 11개와 Node 26개 및 strict 검사를 통과했습니다.
