# 심사 후보 검증 · 2026-10-09

최근 앱 UI 후보는 **0.1.8**, 게임 도구는 **0.1.6**입니다. 0.1.8의 추가 기능 검증은 [대화 저장·초상화 정리](STORAGE_MAINTENANCE.md)에 기록했습니다. 아래는 0.1.7 복구 검증 이력입니다. 심사 통과 또는 신규 계정 전체 검증 완료를 뜻하지 않습니다. 원자적 최초 생성은 여전히 출시 차단 항목입니다.

## 이번에 수정한 복구 동작

- 최초 SDK 연결 실패 후 Refresh로 연결을 다시 시도합니다.
- 생성 응답이 유실돼도 생성 전 화면에서 같은 요청 확인 버튼을 볼 수 있습니다.
- 행동 결과가 불확실한 동안 새 행동·대화·그림 버튼을 잠급니다. 새로고침해도 원래 요청 ID를 유지하며, 같은 요청 확인을 마친 뒤 풀립니다.
- 삭제 응답을 확인하지 못했더라도 새로고침으로 게임이 보존됐음을 확인하면 행동을 다시 허용합니다. 삭제됐다면 종료 화면과 정리 재시도를 표시합니다.

## 자동 검증과 범위

`npm run test:browser`는 실제 배포 UI를 Edge/Chromium에서 열고 Anna SDK 경계에 결정적인 실패를 주입합니다. 테스트 이름은 Recovery buddy입니다. 외부 요청을 차단하고 계정·실제 저장소·유료 AI를 사용하지 않습니다. UI의 판단과 버튼 동작을 확인하며 Anna 서버의 권한 부여, 원자성, AI 품질을 증명하지 않습니다.

| 시나리오 | 확인 내용 |
| --- | --- |
| 최초 연결 실패 | Refresh가 connect를 다시 호출하고 첫 만남 화면 복구 |
| 권한 거부 후 허용 | 오류 안내, 자동 생성 없음, 허용 후 수동 재시도로 생성 |
| 최초 생성 응답 유실 | 보이는 재시도, 같은 ID로 결과 확인, 새 생성 차단 |
| 돌봄 응답 유실·중복 클릭 | 한 번만 적용, 새 행동 차단, 새로고침 후에도 같은 ID 재시도 |
| 상태·부가 저장소 장애 | 연결/대화·앨범 오류 안내, 새로고침 복구와 파트너 보존 |
| AI 응답·대화 저장 실패 | 입력 복원, 미저장 안내, 저장된 대화만 재접속 복원 |
| 그림 업로드 실패 | 저장 재시도에서 AI 생성 횟수 1회 유지, 저장 후 재접속 복원 |
| 360px·언어 전환 | 가로 넘침 없음, 개인정보 창 사용 가능, 파트너 이름 보존 |
| 삭제 요청 응답 중단 | 행동 잠금, 상태 재확인으로 기존 게임 복구 |

Windows는 설치된 Edge를 기본 사용합니다. 다른 환경은 `npx playwright-core install chromium` 후 실행하세요. `ANNA_BROWSER_CHANNEL=chromium`으로 CI와 같은 브라우저를 선택할 수 있습니다. Windows/Linux CI에서도 브라우저 검사를 실행합니다. 호스트 모의 데이터는 게임 규칙 검증용이 아니며 규칙·ETag·재시도 저장 계약은 별도 Python 테스트가 담당합니다.

기존 Node 19개, Python 41개와 strict manifest 검사도 확인합니다. 삭제 정리 중단/재개와 stale CAS 거부는 `data.test.mjs`/`test_privacy.py`에서 검증하고, 실제 APS에서의 삭제 성공·재생성 거부·정리 재시도 근거는 [DATA_REMOVAL.md](DATA_REMOVAL.md)에 따로 기록했습니다.

## 실제 플랫폼에서 남은 확인

| 항목 | 상태 |
| --- | --- |
| 신규 계정 설치·권한 최초 승인 및 거부→재허용 | **미검증.** 기존 계정 초안 업데이트와 UI 오류 주입으로 대신 완료 처리하지 않음 |
| 최종 고정 버전의 신규 생성→돌봄→AI 대화·그림→재접속 | **새 격리 계정/설치에서 필요.** 기존 버전의 실동작 기록은 있으나 이번 후보의 전체 실서비스 검증과 구분 |
| 원자적 최초 생성 | **출시 차단.** Anna 지원 확인 및 서로 다른 실행기의 동시 생성 검증 필요 |
| 데이터 삭제의 진행 중 업로드·구버전 실행기·플랫폼 보관 | [현재 제한](DATA_REMOVAL.md)을 유지. UI 테스트 통과로 해결된 것으로 보지 않음 |
| 비공개 지원 접수 | 연락 경로 확정 필요. 공개 GitHub 이슈에 개인 데이터를 받지 않음 |
| 스토어 화면 일치 | 평상시 화면 구성은 동일. 오류 시 전역 재시도 버튼만 변경. 신규 최종 캡처 대조는 제출 직전에 수행 |
| 심사 제출·공개 | 실행하지 않음 |

불확실한 행동/그림의 재시도 정보는 현재 창 메모리에만 있습니다. 창을 닫으면 같은 요청 확인/생성 그림 저장 재시도를 이어갈 수 없습니다. 다시 열어 저장된 상태를 먼저 확인해야 하며, 새 행동이나 새 그림을 자동으로 실행하지 않습니다. 다른 실행기·구버전 클라이언트까지 잠그는 전역 실행 장벽은 아닙니다.

## 실제 비공개 업데이트 확인

0.1.7(version ID 1202)을 비공개로 고정하고 초안 revision 9를 기존 계정에 설치했습니다. Executa는 기존 0.1.6(version ID 680)을 재사용합니다. UI 96개 파일 중 변경 3개가 업로드됐습니다. 설치 알림에 `Tools NOT deployed (already_satisfied)`가 있었으나, 앱을 닫고 다시 열었을 때 실제 도구 status와 Refresh가 모두 성공했습니다. 이는 도구의 신규 계정 배포 검증을 뜻하지 않습니다.

업데이트 직전과 직후 모두 모찌, 10 / 100 XP, 대화 4개, 로딩된 초상화를 확인했습니다. 새 전역 재시도 버튼의 DOM 위치도 확인했고, 추가 새로고침 후에도 동일했습니다. 본 계정에서 게임 행동·대화·이미지 생성·삭제는 실행하지 않았습니다.

최종 코드 `8b92ed6`의 [Anna Windows/Linux CI](https://github.com/kdkrkwhr/notebook-pets/actions/runs/37927292508)와 [엔진 CI](https://github.com/kdkrkwhr/notebook-pets/actions/runs/37927292421)를 확인했습니다. 로컬 Edge 9개와 Node 19개, Python 41개, strict 검사가 성공했습니다.
