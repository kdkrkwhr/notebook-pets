# 2026-10-17 제한 유료 검사

사용자 승인 한도: Anna 이미지 최대 2회, 텍스트 최대 6회. 실제 사용도 이미지 **2회**, 텍스트 **6회**다. 금액/Anna 차감 토큰의 정확한 청구 내역은 조회하지 않았으며, 모델 응답의 usage와 요청 횟수를 기록했다. 호출 전 브라우저 중계에 한도 차단을 설치했다. 별도 이미지 생성 도구나 BYOK를 대체 검증으로 사용하지 않았다.

## 실제 제공자 결과

- 개발용 `notebuddy-dev` 앱 / `dev-notebuddy-dev` 도구 저장소를 사용했다. 운영 친구·그림·대화에는 유료 테스트를 실행하지 않았다.
- `google/gemini-3-flash-preview`: 성격 생성, 대화, 돌봄 반응, 그림 분석 각각 실제 응답 확인. 앱의 초상화 생성/업로드/파일 저장/로컬 픽셀 변환을 실제 Anna 저장소에서 확인했다.
- 홈 배치: 순수 Python 규칙으로 만든 격리 후보 4개에 실제 모델을 한 번 호출했고, 배포 모듈의 `homeDecision`으로 후보 ID/이유 형식을 검증했다. 실제 방에 배치를 적용한 유료 통합 검사는 아니다. 가구 없는 개발 방에서는 Decorate가 호출 없이 중단됨을 확인했다.
- 산책: 실제 모델 한 번과 배포 모듈의 한국어 이야기 프롬프트/`parseStory`로 두 선택지와 완결된 결말 형식을 확인했다. 실제 산책 보상/선택 저장은 무료 회귀 검사가 담당한다.
- `openai/gpt-image-2`: 초상화 2장, 각 1024×1024 응답. 첫 요청 뒤 오래된 개발용 앱 삭제 표시 때문에 저장이 차단됐다. 표시를 백업하고 개발용 삭제 표시만 정리했으나, 담당자가 앱의 제거 화면에서 대기 이미지가 지워지는 점을 놓쳐 다음 클릭이 두 번째 초상화를 생성했다. 자동 재시도는 아니며, 사용자 한도를 넘지 않았다. 이 실수와 제한을 사용자에게 알렸다. 받은 원본 두 장은 비공개 `.local/paid-audit/`에 보존했다.
- 따라서 **실제 Anna 방향별 이동 시트 생성/판독은 이번에도 미검증**이다. 한도 차단이 추가 이동 이미지 호출을 막았다. 초상화 저장 성공을 이동 준비 성공으로 해석하지 않는다. 여러 체형/진화/장비별 실제 유료 생성도 미검증이다.
- 재접속 및 홈 열기 전후 앱 저장 4종의 값/ETag 동일, 추가 AI 호출 0회. 한도 소진 후 유료 요청은 더 보내지 않았다.

## 발견 및 수정

1. 도구가 활성 친구를 반환하더라도 앱 아트/대화에 삭제 표시가 남아 있으면 UI가 유료 기능을 열었다. 응답을 받은 후 저장이 거부되어 낭비될 수 있다. `readExtras`가 삭제 표시를 발견하면 제거 상태로 전환하고 유료 조작을 차단하도록 고쳤다. 두 저장 키 각각을 재현하는 브라우저 회귀를 추가했다. 삭제 표시를 자동 제거하지 않는다.
2. Windows 개발 연결의 Python 브리지가 CP949로 JSON을 출력해 한글이 깨지고, 이후 `UnicodeEncodeError`로 도구 저장이 실패했다. 개발 실행 스크립트에서 `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`을 전달한다. UTF-8 재실행 후 실제 돌봄 저장과 반응 응답을 확인했다. 이미 손상된 개발용 이름을 자동 복구하지 않았다. 운영 클라우드/배포 바이너리 문제라고 단정하지 않는다.
