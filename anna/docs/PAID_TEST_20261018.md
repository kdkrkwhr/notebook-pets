# 2026-10-18 친구 생성·마이홈 재현 검사

사용자가 진화 검증 완료를 보고했고, 그림·사진 생성부터 마이홈 선택·재입장 검사와 심사 상태 확인을 요청했다. 웹은 이번 작업에서 제외했다. 새 승인 한도는 **이미지 최대 2회·텍스트/비전 최대 2회**, 실제 사용도 **이미지 2회·텍스트/비전 2회**다. 이미지 자동 재시도나 별도 BYOK 호출은 없었다. 정확한 Anna 차감 토큰·금액은 조회하지 않았다.

## 환경과 범위

- `release`의 Anna **1.4.11**, 게임 도구 **0.9.4**를 복사한 격리 개발 앱 `notebuddy-flowcheck-oct18`과 별도 도구 저장소를 사용했다. 검사한 app.js, birth-flow, birth-art, home-sprite, pixel-pet, personality 모듈은 릴리스 원본과 SHA-256이 일치한다.
- 실제 Anna AI와 APS를 사용했다. 참고 자료는 저장소에 기록된 Mori의 새싹 그림 PNG 한 장이며, 파일 불러오기 경로로 선택했다. 실제 사람 사진·다양한 체형을 모두 검사한 것은 아니다. 그림판·사진 교체·실패 복구는 무료 브라우저 회귀로 보완했다.
- 호출 중계에 승인 횟수 차단을 두고 재시작 후에도 횟수를 유지했다. 응답과 원본 생성 PNG를 판독 전에 비공개 `.local/flowcheck-audit/`에 보관했다. 서명 URL, 인증 정보, 원본 응답, 개인 저장 데이터는 커밋하지 않는다.

## 동작·저장 검증

- 초상화 완성 시점까지 이미지 요청은 1회뿐이고, 홈 이동 시트는 자동 생성되지 않았다. 원본·초상화·성격이 저장됐으며, 첫 홈에서 생성/무료 선택을 제공했다.
- 무료 기본 이미지를 선택한 뒤 `home-default-v1` 저장, 실제 캔버스의 캐릭터 표시, 홈 닫기·재입장, 선택창 재등장 없음, 추가 AI 0회를 확인했다.
- 같은 참고 자료로 두 선택 경로를 비교하기 위해 격리 테스트 앱의 아트 기록만 선택 직전 스냅샷으로 되돌렸다. 무료 결과는 비공개 스냅샷에 보존했다. 운영 데이터나 게임 진행 상태는 되돌리지 않았다.
- 이어 생성 선택을 한 번 눌렀다. `home-sprite-v1`, 현재 초상화와 일치하는 source_path, 16프레임, 오류 없는 저장 상태를 확인했다. 홈 재입장 후 방향별 캐릭터가 표시됐다.
- 전체 검사 페이지를 새로 열고 읽기 전용 새로고침을 실행해도 같은 생성 시트가 복원됐다. 선택창은 숨김, 원본·초상화 보존, 알림 오류 없음, 이미지 2회·텍스트 2회 그대로였다.
- 무료 재현 검사 **11개 통과**: 최초 선택·무료 저장·재입장, 생성 실패 기본 이미지 전환, 자동 재시도 방지, 중단된 이동 시트 판독/저장, 그림판과 사진 교체, 받은 초상화 저장만 재시도, 생성 장애 시 같은 친구 보존.

## 검사 환경 문제와 복구

앱 결함으로 오인하지 않도록 다음 개발 도구 문제를 구분했다.

1. CLI 하네스가 앱 KV 요청에 scope를 생략하면 저장 HTTP API의 사용자 공용 기본 범위를 읽었다. 운영 앱과 같은 앱 분리를 보장하도록 검사 중계에서 앱 요청에 `scope:app`을 명시했다. 기존 개발 기록은 읽기만 했으며 덮어쓰지 않았다. 분리된 앱·도구 저장이 비어 있음을 확인한 뒤 생성했다.
2. 사전 검사용 세션 생성이 하네스의 기존 UI 세션을 닫았다. 첫 생성 전송은 불확정 상태가 됐지만, 이미 받은 그림 분석을 유지한 채 같은 행동 확인으로 친구 생성만 복구했다. 그림 분석을 다시 호출하지 않았다.
3. R2 업로드의 CORS는 `127.0.0.1:5182`를 403으로 거부했고, `localhost:5180`과 `https://anna.partners`는 허용했다. 실패는 이미지 생성 전 참고 파일 업로드 단계였다. 기존 참고 PNG를 실제 Anna 브라우저 출처에서 HTTP 200으로 업로드하고 파일 확정·저장만 복구한 뒤, 허용된 localhost 주소에서 저장된 참고 자료로 계속했다. 이후 초상화·무료 픽셀·생성 시트의 업로드와 다운로드는 정상 경로에서 통과했다. 이 복구 과정은 추가 유료 요청을 만들지 않았다.

제품 코드 수정은 필요하지 않았다. 중간 하네스 연결·업로드 복구가 있었으므로 중단 없는 첫 시도 전체 성공으로 기록하지 않는다. 실제 사용자가 겪는 Anna 제공자 장애를 이 한 번의 검사로 모두 배제할 수는 없다.
