# 새로 시작과 삭제 후 재시작

[기술 문서](README.md) · [개인정보 안내](../PRIVACY.md) · [과거 설계·검증](../archive/RESET_HISTORY.md)

현재 UI의 **새로 시작…**은 기존 친구·진행·대화·그림을 정리한 뒤 첫 만남 화면으로 돌아간다. 확인창에서는 새 이름을 받지 않는다. 사용자는 다른 창과 진행 중 요청을 닫고 삭제 범위와 `RESET NOTEBUDDY`를 확인한다. 정리가 끝난 뒤 이름과 랜덤·그림·사진 시작 방법을 직접 고른다. 정리만으로 AI나 새 게임 생성을 실행하지 않는다.

개인정보 삭제로 종료된 게임에서도 명시적 확인을 거쳐 다시 시작할 수 있다. 삭제한 기록을 복구하는 동작은 아니다. 개인정보 삭제 자체는 별도의 `DELETE NOTEBUDDY` 절차이며 [삭제 계약](DATA_REMOVAL.md)을 따른다.

## 프로토콜과 복구

1. `reset/inspect`는 인증된 게임 저장의 ETag와 삭제·진행 중 리셋 상태를 조회한다.
2. `reset/begin`은 정확한 확인 문구, 미리 본 ETag, 안정적인 UUID `reset_id`를 요구한다. 현재 UI는 `name`을 생략한다. 조건부 쓰기로 진행 중 리셋 표식과 첫 만남 후보를 저장한다.
3. UI가 앱 범위의 대화·그림·부가 기록과 초상화 파일을 정리한다. 동일한 리셋인지 확인하고 ETag를 사용하며, 실패하면 정리 완료로 표시하지 않는다. 진행 중에는 일반 게임 행동을 차단한다.
4. 정리가 끝난 뒤 `reset/finish`가 같은 후보를 첫 만남 표식으로 해제한다. 새 요청 epoch와 리셋 영수증은 오래된 요청의 재적용을 막는다. 다음 명시적 시작은 이미 존재하는 첫 만남 저장에 조건부 쓰기를 한다.

창을 다시 열면 진행 중 정리를 이어갈 수 있다. 같은 리셋의 응답이 유실돼도 재시도는 새 친구의 진행을 지우지 않는다. 다른 ID의 리셋과 오래된 미리보기는 거부한다. 구버전 호출과의 호환을 위해 도구는 `name`을 받는 경로도 유지하지만 현재 UI의 일반 흐름은 첫 만남 복귀다.

## 범위와 한계

도구는 앱 범위의 대화·파일을 직접 읽을 수 없다. `finish`는 UI의 정리 순서를 신뢰하며 서버가 모든 범위를 한 트랜잭션으로 확인하는 방식은 아니다. 도구만 호출하는 클라이언트가 정리 확인 없이 완료를 요청해서는 안 된다.

기존 창의 진행 중 대화·이미지 요청을 전역 취소하지 못한다. 플랫폼·AI 제공자의 로그·백업 삭제나 서명 URL 취소도 보장하지 않는다. [동시 최초 생성 제한](FIRST_CREATION.md)도 별개다. 원본 Discord 엔진의 로컬 저장에는 영향을 주지 않는다.

리셋·개인정보·브라우저 회귀 검사는 별도 임시 저장과 모의 SDK를 사용한다. 사용자의 실제 친구를 삭제해서 검사하지 않는다. 현재 설치 버전의 검증 결과는 [최신 인계](../HANDOFF.md)에서 확인한다.
