## 공개 전에 남은 작업

1. **동시 최초 생성**: APS에 없는 키의 최초 쓰기는 조건부 생성이 아닙니다. 서로 다른 실행기에서 최초 생성이 겹치면 프로세스 내부 잠금으로 막을 수 없습니다. 기존 저장의 ETag 충돌 처리는 검증되어 있으나, 첫 생성의 분산 잠금/원자적 생성 방식은 별도 해결이 필요합니다. 임의로 지원하지 않는 조건부 생성 헤더를 가정하지 마세요.
2. **장기 저장 크기**: 엔진의 요청 영수증이 누적됩니다. APS 한도와 실제 저장 크기를 측정하고, 중복 지급 보장을 유지하는 보관 정책을 정해야 합니다.
3. **스토어 정보**: 실제 앱 화면의 소개용 스크린샷과 개인정보/데이터 처리 안내 URL은 아직 비어 있습니다. 대화·이미지·게임 저장의 처리 및 삭제 방법을 실제 동작에 맞게 정리해야 합니다.
4. **기존 운영 도구 적용 범위**: 로컬 파일용 백업·비활동 페널티 작업은 APS 세이브에 연결되어 있지 않습니다. 원본과 동일한 운영 동작으로 설명하면 안 됩니다.
5. 위 검증을 마무리한 후 심사 제출 여부를 결정합니다. 현재 상태를 공개 완료로 설명하지 마세요.

## 재개 방법과 주의점

`anna/README.md`의 로컬 실행 절차를 사용합니다. CLI는 `@anna-ai/cli 0.1.57`, SDK는 uv.lock의 Git 커밋에 고정되어 있습니다. 로그인은 공식 기기 인증으로 갱신했습니다. 토큰은 사용자 설정 폴더에 있으며 Git에 포함하지 않습니다.

- `apps push --no-install-local --profile binary`는 작업 초안을 갱신합니다.
- `apps cut <새 버전>`은 실행 파일을 업로드하고 도구 의존성을 고정합니다. 기존 버전 번호를 재사용하지 마세요.
- Install draft 후 기존에 열려 있던 앱 창은 예전 버전을 가리킬 수 있습니다. **앱 창을 닫고 다시 열어** 검증합니다.
- `already_satisfied`는 추가 배포가 생략되었다는 뜻입니다. 그 문자열만 보고 실행 실패라고 결론 내리지 말고 실제 앱 상태 조회를 확인합니다.
- 이 PC의 WSL 조회가 `REGDB_E_CLASSNOTREG`로 실패하여 Linux 빌드는 GitHub CI에서 수행했습니다. 사용자 OS 설정은 변경하지 않았습니다.
- 개발 앱 ID 451/452/453과 본 앱 450의 저장은 별개입니다.
- Orca 캡처·진단 파일은 작업용 workspace에만 있으며 Git에 포함하지 않았습니다. iframe URL에는 임시 인증 토큰이 있으므로 경로만 출력하세요.
